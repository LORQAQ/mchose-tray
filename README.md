# mchose-tray

迈从（MCHOSE）游戏鼠标的轻量化 Windows 托盘控制台。

纯 Win32 API + C++17，**不依赖 .NET / Electron / WebView / 任何第三方库**，静态链接单文件。

结构参考 [Iris-0109/rapoo-tray](https://github.com/Iris-0109/rapoo-tray)（MIT，雷柏鼠标同类工具）；
**HID 协议层为完全独立逆向实现**——迈从与雷柏的私有协议毫无共通之处。

| 指标 | 实测值 |
| :--- | :--- |
| 工作集（任务管理器"内存"） | **4.6 MB** |
| 私有内存（真正独占部分） | **2.1 MB** |
| 空闲 CPU | **测不出**（25 秒内 0 秒 CPU 时间，<0.01%） |
| 线程 / 句柄 | 2 / 159，长时间运行**零增长** |
| GDI / USER 对象 | 10 / 6，**恒定不增长**（4000 次图标压测增量 = 0） |
| 可执行文件 | 106 KB |

## ⚠️ 必读：不要把 exe 放在受限目录里运行

托盘图标是通过向 explorer 的通知区域窗口发送消息注册的。Windows 的 **UIPI** 会拦截
"低完整性进程 → 高完整性窗口"的消息，此时 `Shell_NotifyIconW(NIM_ADD)` 返回
`ERROR_ACCESS_DENIED (5)`，**程序右下角什么都没有**。

已验证的一个真实触发场景：某个受限工作区（例如带沙箱标记的目录）被打了
`Mandatory Label\Low Mandatory Level` 完整性标签，**从该目录启动的进程一律被强制降为 Low**，
而 explorer 是 Medium，于是图标注册必然失败：

```
PID 11040 (explorer)      : IL = 0x2000 (Medium)
PID xxxxx (从受限目录启动) : IL = 0x1000 (Low)    <- 图标注册被 UIPI 拦掉
```

**因此请用 `deploy.bat` 安装到普通目录再运行**（见下）。程序在 `NIM_ADD` 失败时也会
弹窗给出可操作的指引，而不是静默失败。

## 快速开始

需要 MinGW-w64（GCC 9+）：

```cmd
build.bat      :: 编译 -> bin\mchose-tray.exe
deploy.bat     :: 安装到 %LOCALAPPDATA%\Programs\mchose-tray 并启动
```

`deploy.bat` 做的事：复制 exe 到普通目录 → 清除可能继承的 Low 完整性标签 → 启动。
之后直接运行 `%LOCALAPPDATA%\Programs\mchose-tray\mchose-tray.exe` 即可。

> Windows 11 默认会把**新出现的**托盘图标收进"隐藏的图标"折叠区。
> 首次运行若没在角落看到，点任务栏的 `^` 展开，把图标拖到任务栏上即可常驻。

## 支持机型（多产品适配）

机型参数（VID/PID、DPI 上限、档位数、回报率档数）全部取自机型库 `src/model_db.cpp`，
**不写死在业务代码里**。

| 机型 | VID | 无线 PID | 有线 PID | DPI 上限 | 来源 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **A7 Pro** | `0x5253` | `0x1021` | `0x1020` | 26000 | 【实测】本项目在真实硬件上验证 |
| L7 Pro | `0x5253` | `0x1020` | `0x00B0` | 26000 | 【社区】mouse_tray + 官网规格 |
| A7 V2 Ultra | `0x3837` | `0x100B` | — | 42000 | 【社区】论坛 `lsusb` 实录 + 官网规格 |
| K7 Ultra | `0x3837` | `0x1001` | `0x4150` | 42000 | 【社区】mchose-cli 协议规格 + 官网规格 |
| A7 Ultra V2 | — | — | — | 42000 | 【官网】规格表 |
| A7 V2 Pro | — | — | — | 26000 | 【官网】规格表 |
| AX5 Pro Max | — | — | — | 26000 | 【官网】规格表 |
| A5 Ultra / A5 V2 Ultra / A7 V2 Ultra+ / L7 Ultra / L7 Pro Ultra / M7 Ultra | — | — | — | — | 【官网】在售机型 |

**未识别机型不会失效**：设备会通过推送报文自报型号名，程序按名字匹配机型库；
即使完全没匹配上，也按"同方案默认参数"运行（6 档 DPI、无线 6 档 / 有线 3 档回报率），
并在界面与诊断里**如实标注"未知机型"**，不会假装知道。

### 机型判定为什么不能只看 PID

`PID` 会跨机型复用：`0x1020` 在 **A7 Pro 上是"有线 PID"**，在 **L7 Pro 上是"无线 PID"**。
所以判定优先级是：

1. **设备自报型号名**（推送报文里的 ASCII 字段，最可靠）
2. 接口 VID/PID 精确匹配
3. 该 VID 的通配条目（未知机型）

另外必须区分两个 ID：

| 名称 | 例子 | 用途 |
| :--- | :--- | :--- |
| **接口 VID/PID** | `5253:1021` | 机型识别按它查表（接收器/有线以不同 PID 枚举） |
| 机体 VID/PID | `5253:0010`（`11 06` 回报） | 设备的类型码，不能用来查机型 |

### 用 `--model-scan` 识别你的机型

```cmd
bin\mchose-tray.exe --model-scan
```

```
=== 机型识别（--model-scan）===
设备自报型号 : A7 Pro
接口 VID/PID : 0x5253 / 0x1021   <- 机型识别依据
机体 VID/PID : 0x0000 / 0x0000   <- 11 06 的设备类型码
连接模式     : 1 (2.4G 无线)
机型库匹配   : 已匹配
  匹配机型名 : A7 Pro
  识别状态   : 已识别
  数据来源   : 实测（本机硬件验证）
  DPI 上限   : 26000
  DPI 档位数 : 6
  回报率档数 : 无线 6 / 有线 3
设备实读档值 : 800 1600 3200 6400 26000 26000
```

新机型适配只需在 `src/model_db.cpp` 的 `kPidKnown` 表里加一行：

```cpp
{ L"你的型号", 0xVID, 0xPID无线, 0xPID有线, DPI上限, DPI档数, 无线档数, 有线档数, "来源" },
```

VID/PID 用 `tools/hid_probe.exe 5253`（或 `3837`）读取；若只知道型号名，
加到 `kNameOnly` 表即可按名字识别。

## 功能

- **托盘电量图标**，默认**常驻显示百分比数字**：
  - 数字样式：大号数字 + 颜色随电量 + 底部比例横轨；三位数（100）自动缩小适配
  - 胶囊样式：经典电池外形 + 按比例填充
  - 双击图标在两种样式间切换，选择持久化
  - 颜色：≤20% 红、≤40% 黄、正常蓝、充电绿、休眠/离线灰
  - 无读数时显示 `--`（未连接）/ `zZ`（鼠标休眠）/ `..`（暂无读数）
- **悬停提示**：型号、电量、连接模式、回报率、DPI 档位
- **左键单击**：状态悬浮窗（型号 / 连接模式 / DPI 档位与数值 / 电量 / 回报率 / 固件）
- **右键菜单**：
  - 回报率 125 / 500 / 1000 / 2000 / 4000 / 8000 Hz（按连接模式自动限制档位数）
  - 休眠时间：关闭 / 1 / 3 / 5 / 10 / 30 / 60 分钟
  - DPI 档位切换（第 1~6 档，显示各档 DPI 值）
  - 显示状态悬浮窗、立即刷新、切换图标样式、开机自启、退出
- **写命令带写后回读校验**，成功/失败都会在悬浮窗明确提示，不会静默失败
- **区分"接收器在线"与"鼠标已连接"**：鼠标休眠时显示「鼠标休眠中（接收器正常）」，
  不会误报成"已连接，电量 0%"
- **被动监听**设备主动推送的 `report 0x13`，零写入获取电量
- **自动重连**：连续失败判离线并指数退避重试；explorer 重启后自动重新挂载托盘图标
- **跟随设备的硬件操作**：用鼠标上的 DPI 按键切换档位后，程序约 3 秒内读到新的活动档位并
  更新提示/悬浮窗；右键菜单会在正确的档位上打勾，可用来确认按键是否生效

                                         ::   退出码 0=完整 / 2=鼠标休眠 / 1=其它不完整

不是纸面实现。

## 协议速查

通道：`UsagePage 0xFF01 / Usage 0x0001`，`Report ID 0x11`（20 字节负载）与 `0x12`（64 字节）。
**负载与响应逐字节 XOR 0xFF。**

| 命令 | RID | 方向 | 含义 |
| :--- | :--- | :--- | :--- |
| `11 03` | 0x11 | 读 | 绑定状态 / vid / pid / **连接状态**（由接收器本机应答） |
| `11 04` | 0x11 | 读 | 固件版本（ASCII） |
| `11 06` | 0x11 | 读 | vid / pid / 固件 / 连接模式 / **电量** / 充电 |
| `12 67` | 0x12 | 读 | 全部设置：DPI 档位与档值、回报率、去抖、休眠 |
| `11 41` | 0x11 | 写 | 回报率 |
| `11 0A` | 0x11 | 写 | 休眠 |
| `11 40` / `12 40` | 0x11 / 0x12 | 写 | DPI 档位（简单式 / X-Y 独立式） |
| `13` | — | 推送 | 设备主动上报：子类型 `0xE2`、电量、充电、型号名 |

完整规格、字段布局、**字段映射实测记录**与实现陷阱见 **[docs/PROTOCOL.md](docs/PROTOCOL.md)**。

### 自己动手物理测量回报率

配置读取（`12 67`）只反映设备**存储的档位**，不是真实上报频率。要拿物理数据，
在**你自己的** CMD / PowerShell 里运行：

```cmd
cd tools
gcc -O2 -o polling_rate.exe polling_rate.c -luser32
polling_rate.exe 8 60
```

它会等你第一次移动鼠标后开始计 8 秒（最多等 60 秒），输出报文条数、平均频率、
**最小间隔**与间隔的**中位数/众数**。读法：间隔众数 ≈ `1000 / 回报率`
（1.00 ms → 约 1000 Hz；8.00 ms → 约 125 Hz）。众数比平均值更可靠，不受起止抖动影响。
注意本进程消息循环约有每秒数千条的投递上限，对 4000/8000 Hz 只能给出下界。

> **为什么某些环境下测不了**：若执行环境把进程与交互桌面隔离，该进程收不到鼠标
> Raw Input。`polling_rate.exe` 内置注入自检：用 `SendInput` 注入 400 次位移后
> 仍收到 0 条 `WM_INPUT`，即可判定通道被阻断（若通道正常、只是鼠标没动，注入会收到报文）。

## 常见问题

**右下角没有图标？**
1. 先看程序目录下的 `mchose-tray-gui.log`：
   - `[6] 托盘图标已添加` → 图标已注册，多半是被 Win11 收进折叠区了，点 `^` 拖出来
   - `[!] Shell_NotifyIconW(NIM_ADD) 失败 err=5` → 就是本文开头那个**完整性级别问题**，
     用 `deploy.bat` 装到普通目录再运行（程序此时也会弹窗说明）
2. 若日志显示 `IL=0x1000 (Low)`，说明 exe 所在目录带 Low 完整性标签，必须换目录。

**图标灰色、提示"鼠标休眠中（接收器正常）"？**
鼠标自己睡了，动一下鼠标即恢复，程序无需重启。这是有意区分的状态——否则会显示成
"已连接，电量 0%"。

**提示"未连接"？**
2.4G 接收器没插好，或鼠标切到了有线/蓝牙模式（本项目只支持 2.4G 接收器这条通道）。

**诊断读到全零 / 读失败？**
确认托盘程序没有同时运行（两者会争抢设备命令缓冲）。

**感觉鼠标指针变慢/变"小"了？**
先确认不是系统设置：`设置 → 辅助功能 → 鼠标指针` 或注册表
`HKCU\Software\Microsoft\Accessibility\CursorSize`（默认状态为**未设置**）。
本项目从不修改系统的指针大小。

若是 **DPI 档位被改动**，用本工具查证并还原（`0` 起，第 2 档 = 索引 1）：

```cmd
bin\mchose-tray.exe --dump                :: 看 "DPI 档位" 与 "DPI 档值" 现任哪一档
bin\mchose-tray.exe --set-dpi-stage 1     :: 还原到第 2 档（按 12 67 的活动索引校验）
```

> ⚠️ **用 `tools\mchose_probe.exe mapping` / `dpitest` 做字段映射实验时请注意**：
> 该芯片的特性读会返回**滞后一条命令**的缓冲，`dpitest` 的"自校验还原"因此可能误判成功，
> 把活动 DPI 档位留在错误值上（本项目开发期间真实发生过：1600 DPI 被留成 800 DPI）。
> 实验后请务必用 `--dump` 核对，并与实验前记录的活动索引比对。

## 已知限制与不确定性

1. **回报率有两个字段，语义已实测区分但未最终闭环。**
   `12 67` 的 `byte1` 高半字节是**活动**档位（当前 = 2 → 1000 Hz，与设备推送 `payload[6]` 互证），
   `byte2` 高半字节是 **`0x41` 写命令的落点**。
   实测证实写入确实改变了后者（500Hz→档1、1000Hz→档2，写后回读一致），
   但**前者在写入后并不立刻跟随**——官方软件注释称设置先写 EEPROM、需重载才同步回 RAM。
   界面显示活动字段，写命令作用于写入字段并做回读校验；界面上不做"乐观覆盖"，只显示实读值。
2. **休眠命令**：启用时做回读校验（比对 `12 67` 的 sleep 分钟字段）；关闭时无法从该字段
   区分"关闭"与"保留上次分钟数"，因此只报告"已下发"，不会谎称"校验通过"。
3. **DPI 档位有两个索引，语义不同。**
   `byte1` 低半字节是**活动**档位（界面显示它），`byte2` 低半字节是 `0x40` 写命令的落点。
   实测：写完 `0x40` 后写入字段**立刻**变化，活动档位要等设备同步才跟随，
   因此"写后活动档位暂时等于写前值"是正常现象，不是写失败。
   DPI 档位切换采用"读全量 → 只改目标字段 → 整包回写 → 写后回读（任一索引匹配即算生效）"。
4. **硬件实测只覆盖 A7 Pro。** 其余机型的 VID/PID 与规格来自社区记录与官网规格表
   （见"支持机型"表），**未经本机硬件验证**。协议层（`0xFF01` 控制集合、
   `0x11/0x12/0x13` 报文、负载 XOR 0xFF、推送子类型 `0xE2`/`0x1D`）
   已被两份独立社区来源交叉印证用于 L7 Pro 与 K7 Ultra，但回报率档位列表
   （125/500/1000/2000/4000/8000）与休眠取值集合仍按 A7 Pro 的参数处理。
   换机型请先跑 `--model-scan`，并把结果反馈以补全机型库。
5. **蓝牙模式未涉及**，很可能没有配置通道。
6. **物理回报率未在开发环境实测**（进程与交互桌面隔离，收不到 Raw Input）；
   当前 1000 Hz 来自设备自身报告（配置字段 + 推送索引两处互证）。

## 代码审查与修复记录

经过一轮独立的只读代码审查（两个子代理分别覆盖设备层与界面/协议层），
完整报告与**逐条处理结论**见 [docs/CODE-REVIEW-2025.md](docs/CODE-REVIEW-2025.md)。

已修复的主要缺陷：

| 级别 | 缺陷 | 影响 |
| :--- | :--- | :--- |
| 高 | 菜单 ID 区间重叠：休眠分支的宽区间吞掉全部 6 个 DPI 档位 ID | 点「DPI 第 N 档」实际下发 99~104 分钟休眠（会写 EEPROM）。已修，并加 `static_assert` + `--selftest` 33 项检查覆盖 |
| 高 | `snprintf` 返回值被当作写入长度 / 当作累积偏移 | 潜在栈越界。已引入 `AppendFmt()` 显式夹紧 |
| 高 | `ReadPush` 放弃在途重叠 IRP | 真 UB：迟到完成写入失效栈帧；陈旧事件信号导致推送句柄被误关。已改为常驻 `OVERLAPPED` + `CancelIo` 后阻塞收割 |
| 高 | **宽字符格式化误用 `%s`** | 本工具链下 `%s` 是**窄**语义，宽串必须 `%ls`：导致提示/悬浮窗文字乱码、日志文件名变成 `Cmchose-tray-gui.log`。已全部修正并加自检断言 |
| 中 | 每 9 秒无条件发布 `CHANGE_SETTINGS` | OSD 周期性弹窗。已改为仅在设置真变化时发布，`--watch` 回归验证 |
| 中 | 推送句柄读失败后永不重开 | 被动通道一次错误即永久死亡 |
| 中 | 未区分"接收器在线"与"鼠标已连接" | 鼠标休眠时显示"已连接，电量 0%" |
| 中 | 写后立即回读会读到写入前的旧设置 | 写校验假失败。已加稳定期 + 双读 |
| 中 | `RequestRefresh` 被消费后丢弃 | "立即刷新"与单击托盘不生效，最长陈旧 9 秒 |
| 中 | `Stop()` 超时后仍关闭线程仍在等待的事件 | 停止事件已改为经线程参数传递的稳定副本 |
| 中 | `failStreak` 双计数、成功推送不清零 | 离线误判 + 通知风暴。已改为每轮最多 +1、任何成功清零，并加指数退避 |
| 中 | 每轮循环都读 `11 03` | 空闲 CPU 从 0.01% 级被抬到 0.156%。已按 3 秒节拍读，降回测不出 |
| 中 | **explorer 重启后图标不回来** | 外观缓存导致跳过 `NIM_MODIFY`。已在 `TaskbarCreated` 里失效缓存并重组 `g_nid` |
| 低 | 旧图标在 `NIM_MODIFY` 之前被销毁 | explorer 持有已释放 HICON |
| 低 | 数字样式的电量横轨完全不显示 | 画文字时误用 `SelectObject(hdc, old)` 把 DIB 取消选中，横轨画到了别处 |
| 低 | `CreateCompatibleDC` 失败未判空 | `SelectObject(NULL,…)` UB + 位图泄漏 |

被审查提出但**复核后驳回**的两条：OSD 淡出"传负 alpha"（代码在 `a <= 0` 时直接隐藏）、
以及"放宽全零判据以兼容合法全零状态"（放宽后实测会把滞后缓冲当有效数据，显示
"电量 0%、回报率 125 Hz"的垃圾值，属于**静默错误数据**，比读不到更糟）。
详情见 [PROTOCOL.md](docs/PROTOCOL.md) 第 10 节。

### 性能优化记录

| 项 | 优化前 | 优化后 | 做法 |
| :--- | :--- | :--- | :--- |
| 空闲 CPU | 0.156% 单核 | 测不出 | `11 03` 链路读取改为 3 秒节拍（原先每轮循环都读） |
| 工作集 | 12.2 MB | **4.6 MB** | 启动完成后一次性 `SetProcessWorkingSetSize` 裁剪（私有内存不变） |
| GDI 抖动 | 每次状态通知重建图标 | 外观未变则完全不动 GDI | 图标/提示文本按内容缓存，未变化时不重建、不打扰 shell |

### 工具链陷阱（供二次开发者注意）

本工具链（MinGW-w64 + msvcrt）下 **`swprintf` 的 `%s` 是窄字符串语义，宽字符串必须用 `%ls`**，
写错不会产生任何编译警告，只会得到乱码。项目已用 `--selftest` 中的断言把它钉住：

```
宽字符 %ls 格式化 -> "[OK]" OK
```
